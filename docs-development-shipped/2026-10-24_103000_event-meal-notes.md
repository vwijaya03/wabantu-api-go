## Apa yang di-ship

1. Kolom `evt_event_person.meal_notes TEXT NULL` + `ALTER ... ADD COLUMN IF NOT EXISTS` di `eventsSchemaPatchSQL`; dicek di `EventsModuleReady`, `eventsPersonPatchReady`, dan `ensureEventsMissingColumns` agar tenant lama ter-upgrade otomatis.
2. Field JSON `mealNotes` (opsional) di `UpsertPersonParams`, `EventPerson`, `PublicStaffRegisterBody`, dan `PublicStaffMonitorPerson`.
3. Validasi di `normalizeMealNotes` (`events/meal_notes.go`): trim, kosong → NULL, maks 200 rune (lebih → 400 InvalidArgument), `countsTowardMeals=false` → NULL.
4. Karakter NUL (`\x00`) ditolak 400 InvalidArgument — Postgres TEXT menolak byte 0x00 (SQLSTATE 22021) sehingga sebelumnya bisa jadi 500. `mealNotes` → "catatan konsumsi berisi karakter tidak valid" (di `normalizeMealNotes`); `notes` → "catatan berisi karakter tidak valid" (di `validatePerson`, dipakai create/update person dan daftar staf publik). Temuan QA 24 Okt.
5. Ditulis di semua jalur insert/update (create/update person, `createPersonInEvent` untuk publik & import roster) dan disalin saat duplikat acara.
